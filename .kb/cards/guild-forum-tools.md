## Purpose
UX pass over the forum v2 (`guild-forum-v2`): (1) a compact **secure formatting toolbar** (Gras / Italique / Nuancier) on edit fields — it only inserts the text markers `fmt` supports (`**x**`, `*x*`, `#rrggbb`), and every rendering still goes through `fmt` (HTML escaped first), never raw HTML; the color code is always inserted **space-separated** so the preview actually shows the color, with replace-in-place / idempotent semantics; (2) **topic edit rights** — the pencil shows only for the topic author, `create_topics` holders, or holders of the parent category's write right (mirrors the back 403, card `guild-forum-edit`); (3) **header cleanup & typography** — the redundant top-right « + » button is gone (creation happens exclusively through the add card), the contextual back button is strictly left, forum titles are slightly larger, a centered five-dash separator `-----` separates title from description, and descriptions are larger; (4) **factorisation** — one shared `AddCard` (ranks / categories / topics) with the insertion toggle on the action-buttons line (ranks layout), and one shared `DndList` owning the arrows + drag & drop + golden insertion line for all three lists; (5) **in-place editing** — a generic `InlineField` component: the tag that displays the text **itself** becomes the input (no new field is ever created), first used on forum category/topic titles+descriptions and the topic-view header.

## How it works
All UI in `src/components/Guild.jsx`, shared widgets in `src/components/fmtbar.jsx` / `InlineField.jsx`, pure helpers in `src/lib/`:
- **`FmtBar({ onFmt, onColor })`** (in `fmtbar.jsx`) — one compact row: `B` → `onFmt('**')`, `I` → `onFmt('*')`, a color swatch (`<input type="color">`, default `#c8a24a`) → `onColor(hex)`, applied **on the picker commit** (`onChange` only — `onMouseUp`/`onTouchEnd` never fire while the native color dialog is open; that was the silent “color does nothing” bug). Placed **above** the edit fields in `NewTopicModal` / `NewFolderModal`, in the reply row, and inside `InlineField`'s open state.
- **`useFmt()`** (in `fmtbar.jsx`) — `bind(setter)` is spread on a target `<input>/<textarea>` and returns **both** `onFocus` (captures `{ el, set }` in a ref) and `onChange` (`e => set(e.target.value)`) — a controlled field without `onChange` is frozen by React (read-only; that was the “cannot add/delete text” bug), so the spread guarantee keeps every bound field editable. `fmt(marker)` / `color(hex)` resolve the *last focused* field and run the pure **`wrapSel(value, s, e, before, after = before)`** / **`colorSel(value, s, e, hex)`** (`src/lib/fmt.js`) over the element's live `value` + `selectionStart/End`, call `set(text)`, and reposition the caret with `requestAnimationFrame(() => el.setSelectionRange(cursor, cursor))`.
- **`colorSel` v2 semantics** (`src/lib/fmt.js`, unit-tested): the code is inserted after the selection with a **guaranteed space before the code** (that space is exactly what `fmt`'s standalone-hex regex requires to render the color in the preview — the old glue-less insertion is why the preview never colored); if the caret sits just after an existing `#rrggbb` code, the new color **replaces** it (color change, no stacking); a duplicate click on the same code is a **no-op**.
- **`FPrev({ text })`** (in `fmtbar.jsx`) — live “Aperçu” box (`div.fprev`, dashed border, `.95rem`) rendered **below** a text field: it shows the `fmt`-rendered result of what the user is typing, so the formatting outcome is visible without reading the markers (“voir le résultat, pas le code”). Rendered through `fmt` (escape-first) — XSS-safe; hidden when empty. Placed under: new-topic content, new-folder description, the reply input, and `InlineField`'s open state.
- **Safe rendering**: titles/descriptions now render through `dangerouslySetInnerHTML={{ __html: fmt(...) }}` (folder & topic names, `.fdesc` lines, the topic-view `<h4>`): `fmt` escapes HTML **before** turning `**`/`*`/`#rrggbb` into tags, so user HTML stays inert — verified by `test/fmt.test.js` (`fmt(wrapSel('<img src=x>', 0, 11, '**'))` → `<b>&lt;img src=x&gt;</b>`).
- **Edit gating**: `canEditTopic(t, f, gme, uid)` (`src/lib/guild.js`, pure, unit-tested) = `gme.leader || t.author_id === uid || gme.permissions?.create_topics || (f.write_ranks ?? []).includes(gme.rank)` — the exact mirror of the back gate; the topic pencils (list view + messages view) use it, the category pencil stays `create_topics`-only. The back now returns `author_id` in every topic row (`GET /guilds/{characterId}`).
- **`AddCard({ i, len, onOpen, dnd, below, setBelow, label, canMove, onMove })`** — the single add card for ranks/categories/topics: `.radd` grid `1fr auto 1fr` (empty left spacer, big `+` in the bordered circle centered, `.aacts` on the right = **insertion toggle + `Arrows`** — the ranks layout; the forum add cards now match it). Card body / `+` open the create modal (suppressed right after a drag via `dnd.justDrag`); the toggle label `stopPropagation`s so toggling never opens the modal; `canMove` renders the ↑/↓ `Arrows` (forum: only with `create_topics`).
- **`DndList({ rows, onReorder, renderRow, className = 'dlist' })`** — owns `useDrag` (8 px arm threshold), the container ref (`.dlist` is `position:relative`), the golden `.inl` insertion line, and maps `renderRow(row, i, dnd)` per display row (add sentinel → `AddCard`, else a `.rcard`/`.fcard` with `dnd.rowProps(i)` + `.rkdr` while dragged). On drop it calls `onReorder(from, to)`; the parent recomputes ids with `dropRankRow` and persists via `POST /guilds/reorder` only when the real order changed. Consumed by `Manage` (ranks) and `Forum` (folders, topics) — the per-list `useDrag`/`rowProps`/`.inl` boilerplate was deleted.
- **`InlineField({ value, display, pencil, canEdit, multiline, rows, placeholder, fmt, onSave })`** (`src/components/InlineField.jsx`, **generic — reusable in any component**) — in-place editable field: the display element (`display(t)`, default `<b>{t}</b>`) **transforms itself** into an `<input>`/`<textarea>`; **no new field is ever created** in the page flow. Enter = save (in a textarea, Shift+Enter inserts a newline), Esc = cancel; with the `fmt` prop the open state gains the `FmtBar` (B/I/#) + `FPrev` live preview of the draft. `onSave(v)` returns a Promise the parent owns: **resolve** → back to display; **left pending / rejected** (parent toasted the error) → the field stays open. An optional built-in pencil (`pencil && canEdit`) is for standalone use; the forum passes `pencil={false}` and keeps its own trigger in the row actions / header.
- **Forum in-place editing** (`Guild.jsx`): the `InlineEdit`/`.edbox` box was deleted. List rows (category & topic) and the topic-view header render their title/description display tags normally, and when the item is being edited (`fEd`/`tEd` = the target id) **those exact tags are replaced by `InlineField` inputs** in the same slot (`.infield` CSS: centered column, `max-width:440px` inputs, “Entrée : enregistrer · Échap : annuler” hint). `saveFold`/`saveTopic` wrap `POST /guilds/{folders,topics}/{id}/edit` through `run` (house toast idiom) and keep the promise **pending on error** — so a 403/500 leaves the field open instead of silently discarding the draft; success triggers `load()` (value refreshed) and closes the field. An empty description line becomes editable too (you can add a description to an item that had none).
- **Headers**: `.fhead2` grid lost its right « + » button; `.fhead2 .backbtn{ justify-self:start }` (strict left); `.fhead2 .rhead{ font-size:1.6rem }` (ranks stay 1.4rem); `.fdesc` .9rem/opacity .8; `.fsep` = exactly `-----` centered, rendered only when a description exists (topic view, messages view; category-list view has no section description). The header block carries no background/border of its own.

## Entry points
- `src/components/fmtbar.jsx` (`FmtBar` / `FPrev` / `useFmt`) — the secure toolbar, live preview and the last-focused-field binding; `src/components/InlineField.jsx` — the generic in-place editor (reusable in any component; also `NewTopicModal` / `NewFolderModal` modals and the reply row keep their static `FmtBar`/`FPrev`).
- `Guild.jsx:AddCard` / `:DndList` — the single shared add card and reordering controls (ranks, categories, topics).
- `src/lib/fmt.js:wrapSel` / `:colorSel` and `src/lib/guild.js:canEditTopic` — pure helpers (unit-tested; import anywhere).
- Back API: `POST /guilds/{folders,topics}/{id}/edit` (403 rules — card `guild-forum-edit`); topic rows carry `author_id`.

## Data flow
- Toolbar: click B / I / # → `useFmt` resolves the last focused field → `wrapSel`/`colorSel` (pure, no DOM read beyond selection) → `set(text)` → React re-render; on submit/render the text displays through `fmt` (escape-then-format). No raw HTML ever reaches the DOM; `fmt` is the only rendering path.
- Edit gating: `GET /guilds/{me}` → topic rows carry `author_id` → `canEditTopic(t, f, g.me, me.id)` shows/hides the pencil → `POST /guilds/topics/{id}/edit` re-checks server-side (author / create_topics / **category** write) → 403 otherwise → `load()` re-syncs.
- Reorder: press & glide a row (8 px) → `.rkdr` (opacity .45) + `.inl` measured line → drop → `dropRankRow` → `persistF`/`persistT`/`persistOrder` → `POST /guilds/reorder` only when the items' order changed (the add card's own position stays session-local).

## Gotchas
- **Controlled field without `onChange` = frozen input**: React makes a `<input value=…>` read-only when no `onChange` is provided (dev warning + read-only behaviour). Every field spread with `bind` gets `onChange` for free (guarded by the static test against `fmtbar.jsx`) — never write a controlled input that neither spreads `bind` nor has an explicit `onChange`.
- **Color codes must be space-separated or the preview never shows the color**: `fmt`'s color regex requires a standalone hex (`(^|\s)#rrggbb(\s|$)`) — `colorSel` v2 therefore always glues the separating space, and *replaces* the code just under the caret (picking a new color where one was inserted = clean swap, no `#a#b` stacking); a same-color duplicate click is a no-op.
- **Native color pickers swallow `mouseup`**: `onMouseUp`/`onTouchEnd` on `<input type="color">` never fire while the OS dialog is open (the pointer event happens inside the dialog) — apply the color on `onChange` (commit).
- **`saveFold`/`saveTopic` keep the save promise PENDING on error**: `run` toasts and swallows the failure, so the parent promise never settles → `InlineField` stays open (no silent draft loss). On success it resolves *after* `load()` — the refetched value reaches the now-closed field harmlessly.
- `useFmt.bind` stores the setter in a ref **on focus**: the toolbar acts on the last focused field; a never-focused field is a no-op (no crash). The caret reposition is deferred to `requestAnimationFrame` so React has committed the new value first. Clicking the B/I/color controls blurs the text field but the browser keeps its selection, so `selectionStart/End` stay valid.
- `InlineField` seeds its draft **on open** (`setV(value)` in `start()`): re-opening the same target shows the current server value; a `load()` while open leaves the visible draft stale until re-open — accepted. Its `FPrev` tracks the *draft*, not the saved text.
- `DndList` takes its row renderer **only** through the `renderRow` prop: passing a function as JSX children crashes at `rows.map` (`renderRow is not a function`) — the real regression of this card's first commit; all three call sites (Manage / forum folders / forum topics) pass `renderRow={(row, i, dnd) => …}`, guarded by the static test in `test/guild.test.js`.
- Topic pencil gating is `canEditTopic`, **not** `can`: a rank holding only the category write right sees topic pencils but no category pencil; the reorder arrows stay `create_topics`-gated. The back 403 is authoritative — the front mirror only hides the gesture.
- The header « + » is gone: the add card is the only create entry point and it still renders for everyone (creation by a non-`create_topics` member 403s and toasts) — mirrors the previous behaviour, not a regression.
- Never inline a `dangerouslySetInnerHTML` with raw user text: the only sanctioned pattern is `__html: fmt(text)` (escape-then-format). `fmt` must stay the single rendering module for forum text — `FPrev` and `InlineField`'s display/preview obey it too.
